### N1 [low] Undo after typing in Creator details does nothing to the box; on 7.1, undoing back to the saved value loses the typed text with no warning and Ctrl+S ignores it
- actual: Each typed character is a separate undo step that changes only the editor store, never the box. On 7.1, after the Undo clicks, isEditedPostDirty is false while the box shows 'Undo2 town 71b Typed' and the store holds the saved 'Undo2 town 71b'. Ctrl+S sends no request, leaving shows no dialog, and the typed text is lost (stored value unchanged). Seen three times on 7.1 (dirty4-71b, dirty4-71c, undoshot-71). After a single Undo, Ctrl+S saves the box text, so Undo looks like it did nothing. The Save button still saves the box. On 6.5 the post stays dirty after the Undo clicks and Ctrl+S saves the box text.
- cause: The sync script dispatches editPost({meta}) on every input event, so core records one undo level per keystroke. Undo reverts only the store's meta edit, and nothing writes the reverted value back into the box. When the store returns to the saved value, core drops the edit and the post is no longer dirty. The box's values go out only with a save the editor thinks is needed. Options: subscribe to the store and set each box input to the edited meta value when it changes from outside the box; or mark edits from the box as non-undoable (for example editPost(..., { undoIgnore: true }) where supported); or keep a separate dirty flag for the box that blocks the leave and forces the meta-box save.
- steps: wpt new <name> <port> seeded71, log in as admin, Creators > open Jess, open Meta Boxes / Click Hometown, press End and type ' Typed' (or select it and type a new town) / Click the editor's Undo button in the top bar once: the box still shows the full typed text, while only the last character is gone from the editor's copy / Keep clicking Undo until it is greyed out (six clicks for ' Typed') / Press Ctrl+S, then click Creators in the admin menu
