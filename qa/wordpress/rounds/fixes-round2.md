## page
- EDI-N01 [fixed] Root cause was functions.php:147 (HEAD). The pattern ([^\s<>]+)(closing inline tags)*</hN>$ picked the bare '.' after </strong> or </a> as the last word, and the strlen>1 test let it through. gm_mark_here() now walks the tags and text from </hN> backward. It drops trailing spaces, &nbsp; and <br>. It reads the last visible character: a '.' is removed and becomes the dot, while ? and ! stay with no dot. It then collects the last word across inline tags, wrapping each piece in span.here, with the dot after the last letter.
- SEC-N05 [fixed] Root cause was functions.php:143 (HEAD). The pattern (?:\s|&nbsp;|<br\s*/?>)+(</hN>\s*)$ backtracks on long gaps until PCRE hits its JIT stack limit. preg_replace then returned null, which was assigned to $html, and preg_replace_callback turned that into ''. The gold-word code now trims gaps with a linear byte scan (gm_gap_before / gm_trim_gap) and needs only one possessive, quote-aware preg_split. Any preg failure returns the original markup, and the k-bars and section-id replacements also fall back to $html on null.
- EDI-N04 [fixed] The editor draws the dot with .gm-here::after in editor.css, which cannot see the last character. functions.php adds a small inline script on enqueue_block_editor_assets (deps wp-hooks, wp-compose, wp-element). Through editor.BlockListBlock, it adds the class gm-nodot to a core/heading with class gm-here when its text, with tags stripped and nbsp counted as space, ends in ? or !. build_theme.py EDITOR_ADDITIONS gets .gm-here.gm-nodot::after{content:none}. Needs editor.css regenerated.
- EDI-N05 [fixed] patterns/hero.php Description now reads: '...The last word of the headline turns gold and gets the pulsing dot on the page, even if it is bold or a link. A final period becomes the dot; a headline that ends in a question mark or an exclamation mark keeps it and gets no dot.' copy_check.py reports ok.
- EDI-N06 [fixed] Cause confirmed in core: TemplatePartContentPanelInner (wp-includes/js/dist/editor.js about line 98384 in 7.1.3) lists every block whose type has category === 'theme'. The Part block had category 'theme'; core paragraphs (text) and buttons (design) never qualify, and only core can change that. The Part block's category is now 'design' (inserter:false, so no other effect), and the Template Part tab no longer lists the two pieces that have nothing to edit. The labels and the button stay editable in the canvas and List View. WordPress 6.5 has no such panel.
- SEC-N07 [fixed] Added if ( ! defined( 'ABSPATH' ) ) { exit; } after the header docblock in patterns/about.php, not-found.php and no-results.php. The pure-markup patterns are unchanged and return their static block markup, which is harmless.
