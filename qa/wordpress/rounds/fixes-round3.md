## styles
- ED-R1 [fixed] theme.json blockGap is now '0px'. In posts and pages a Gallery gets --wp--style--gallery-gap-default:16px, the default WordPress documents for themes, and its flex gap is set to var(--wp--style--unstable-gallery-gap). The image widths and the gap now use the same value on 7.1, where the theme's .5em flex gap used to apply. The same rule, copied for the post editor at higher specificity, beats core's editor display:block, so the editor shows the row as well.
- ED-R2 [fixed] A Button's Width takes var(--wp--style--block-gap) off its share, but the buttons' real gap is 18px. .wp-block-buttons now sets --wp--style--block-gap:18px next to gap:18px, and theme.json blockGap has a unit. Widths of 25, 50, 75 and 100% now fill the row exactly. This also covers the 7.1 dimension-preset Width, which uses the same variable.
- INS-N02 [fixed] The open part was the gallery, button widths, Row vertical alignment and Grid columns. These are fixed under ED-R1, ED-R2 and ED-R3. The round 2 parts still match the round 2 results exactly: Columns gap, Buttons flex, pagination, separator, cite and axe.
- ED-R3 [fixed] I chose to make the controls work rather than hide them. On the page, gm_layout_values runs for flex and grid blocks rendered in post content. It calls core's own wp_get_layout_style (no gap, fallback .5em) with a hashed class, so core prints the per-block rule. The selector is scoped to main.gm-page and stops at front-page sections, like the theme's other reading rules. In the post editor, a small inline script sets the same declarations on the block wrapper. It skips templates, template parts and front-page sections. It also shows a child's own Fit, Grow or Fixed size and its column or row span, which core prints on the page but leaves out of the editor while layout styles are off.
- ED-R4 [fixed] WordPress reads the user's global styles through wp_theme_json_data_user (front end and post editor settings) and through the REST API (Site Editor Styles and its revisions). Both paths now drop font families and every font choice (fontFamily, plus the fontWeight and fontStyle the picker saves with it; the theme has no weight or style control). Appearance > Fonts is removed from the menu, which also removes the Fonts button on the theme details. A direct visit to font-library.php gets a short 403 note with a link back to Themes. The saved post stays as it was until the next Styles save, which stores it without the fonts. Reset styles is not needed.
- ED-R8 [fixed] Same filters as ED-R4. A fontFamily that points at the 3.1.0 presets (var:preset|font-family|label or body), at the root, in elements or in blocks, is no longer read, so the canvas keeps the theme's faces.
- E08 [fixed] The open part was Appearance > Fonts on 7.1 bringing back font pickers. That is covered by ED-R4. The Styles survey with a saved font now matches the E08 baseline (no Fonts section, elements with text alignment only).
- FR-R2 [fixed] The full-width rule in WP_ADDITIONS now also matches the block's own output placed straight in a page (.gm-entry>section.block, the roster, and .gm-entry>section.stories, the stepper or the empty note). - E01 [fixed] The open part was the block placed alone in a page. Fixed under FR-R2. The round 2 roster rerun still shows every town in full, display:block, white-space:normal and no text-shadow.
- FR-R3 [fixed] .roster .tile .who .n gets white-space:nowrap, so its auto column keeps the width of '09'. The name gets min-width:0 and overflow-wrap:anywhere, so a long name wraps inside its column instead of overflowing.

EDITOR_ADDITIONS adds '.gm-bar nav p{margin:0}'. E16 and COM-N04 are untouched: the bar still wraps and grows in narrow canvases.
- EDI-N03 [fixed] The open part was the Part blocks. multiple:false cannot apply because the header holds two Part blocks, so the check is by name. ## script
- FR-R1 [fixed] Cause confirmed: the back rule `else if (k < g - 1 && g - 1 >= zone) goTo(g - 1)` corrected every back swipe that started in the end stretch and travelled more than one card, wherever it ended. It is now `else if (k === g - 2 && k >= zone) goTo(g - 1)`. A back swipe is corrected only when it passed exactly one card and stopped inside the end stretch or on its first card. - FR-R4 [fixed] Reproduced on WP 7.1: after the turn, focus was on BODY in 7 of 7 cases and the next Tab went to 'Follow along'. A trace showed why handling it in the change handler alone fails half the time. The sheet hides on the desktop layout, and Chromium often drops focus to the body before the resize and media query change events run. Now the existing document focusin listener also records the last focused element (held). When the phone layout stops applying while the sheet is open, the handler uses the active element, or held if focus has already dropped to the body. If that was a sheet link or the menu button, the handler closes the sheet and focuses the same link in the bar (About, Creators, Follow, Get the newsletter). The menu button maps to the bar's first link.
- ED-R5 [fixed] Added overflow-wrap:anywhere to `.hero h1` in the shared CSS, so it reaches style.css, editor.css and the v2 page. break-word is not enough here. A web address as the last word now wraps inside the blue hero with the dot after '.org' at every width.
