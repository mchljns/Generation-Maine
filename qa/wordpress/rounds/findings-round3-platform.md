### PL-R2 [low] A change made only in Creator details is not saved by Ctrl+S, and leaving the editor loses it without the unsaved-changes warning
- template: clean71 and clean65 with the zip installed through the UI and the README seed
- steps: Log in as admin, Creators > open any creator, open Meta Boxes / Click Hometown, select its text, type 'CtrlS town', press Ctrl+S, wait, then read the meta with wpt wp <name> post meta get <id> gm_hometown / Change Hometown again and click Creators in the admin menu / Repeat the last step changing the title instead
- expected: Ctrl+S saves the creator as the Save button does, or leaving with unsaved Creator details warns as a title change does.
- actual: Ctrl+S sends no request (isEditedPostDirty is false) and shows nothing; the old Hometown stays. Leaving after a Creator details-only change shows no dialog and the change is lost, while a title change triggers the beforeunload dialog. Clicking Save (or Tab to it and Enter) saves both requests. Same on 7.1.3 (twice) and 6.5.13. I tested the Hometown field; Place on the page is the one field the theme wires to the editor store.
- likely cause: Core's save shortcut and its unsaved-changes check look only at the editor store, and edits in a classic meta box form do not mark the post dirty (core behavior, not a regression of round 2). All creator fields except Place live in that form. The block-editor script added in gm_creator_editor_assets() already calls editPost for Place on the page; it could mark the post dirty on input anywhere in #gm_creator_details so Ctrl+S and the leave warning work, or the README could say to click Save.
